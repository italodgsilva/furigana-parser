# MPV Integration

## Goal

Play a video with the furigana subtitle generated by the pipeline, with no manual
intermediaries.

The flow is:

```text
SRT
 ↓
Furigana Parser (pipeline)
 ↓
ASS (next to the SRT)
 ↓
MPV (--sub-file)
```

## How it works

The `mpv` layer is deliberately simple and decoupled from the pipeline. It only
assembles and runs the command:

```text
mpv --sub-file=<subtitle.furigana.ass> <video>
```

It does **not** know SRT, Kuromoji, Jisho or the `FuriganaDocument`. ASS generation
remains the responsibility of the output layer (`AssGenerator`), orchestrated by
`Application`.

The process execution is abstracted by `ProcessRunner`, which makes it possible to
test the integration without opening the player. The default implementation
(`DefaultProcessRunner`) uses `ProcessBuilder` with `inheritIO()`, so that MPV's
terminal works normally.

## Usage

```text
furigana-parser --mpv <input.srt> <video>
```

Alias: `play`.

Steps performed:

1. the pipeline processes the SRT;
2. the ASS is written next to the SRT, with the suffix `.furigana.ass`;
3. the video is opened in MPV with `--sub-file` pointing to the generated ASS.

Examples of the generated file name:

```text
episode.srt     → episode.furigana.ass
episode.ja.srt  → episode.ja.furigana.ass
```

## Limitations

- **MPV required on the `PATH`.** If the executable is not found, the error message
  guides the installation and the exit code is an error. The tool does not try to
  install or locate MPV in alternative paths.
- **Subtitle overwritten.** The ASS is regenerated on every run and always writes
  to the same path derived from the SRT, overwriting the existing file.
- **No dynamic updates.** The integration only starts the player. There is no
  real-time communication nor subtitle regeneration during playback.
- **Fixed resolution.** The ASS uses `PlayResX/PlayResY = 1920x1080` and
  character-grid positioning. Videos with an aspect ratio other than 16:9 may shift
  the furigana; Latin passages have approximate alignment (see
  `docs/ass-format.md`).
- **CJK font.** The alignment assumes a font with full-width characters
  (kanji/kana occupying ~1 em). If the configured font does not exist on the
  system, MPV falls back and the metrics may vary.
- **Subtitle tracks.** `--sub-file` adds an external subtitle, but tracks embedded
  in the video are not managed; you may need to select the track in MPV.
- **Video provided explicitly.** There is no automatic discovery of the video from
  the SRT (related names/folders are not guessed).
- **No synchronization adjustment.** `Application` does not apply a time offset;
  the subtitle inherited from the SRT is used as is.
- **Readings depend on the network on first use.** Jisho's fallback requires
  internet for terms unknown to Kuromoji; after that, the local cache allows
  offline use.
- **Foreground execution.** The Java process waits for MPV to finish; there is no
  detached/daemon mode.
- **Linux only.** The project is developed and tested on Linux; behavior on Windows
  is not supported.

## Future scope

The architecture foresees, for later:

- Lua script(s) in MPV;
- shortcuts;
- automatic subtitle loading;
- communication between the application and MPV;
- dynamic subtitle updates during playback.

None of this is part of this stage.
